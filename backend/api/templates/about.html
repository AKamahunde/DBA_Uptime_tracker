Database Management Hub

The Database Management Hub is a centralized monitoring and reporting platform developed to assist Database Administrators (DBAs) in managing database operations across Oracle, MySQL, PostgreSQL, and Microsoft SQL Server environments.

System Overview

The platform combines manually entered operational records with automatically collected infrastructure metrics to provide a centralized operational dashboard. Operational information collected through the application is stored within a centralized MySQL database and presented through interactive dashboards and reports.

Security & User Permissions

Standard Users Basic Privileges

Standard users are permitted to view dashboards, create operational records, and view the audit history timeline. To protect record integrity, they can only edit manually entered records within a strict **five-minute** window from creation. After five minutes, records become read-only.

Administrators Full Access Control

Administrators retain full read, write, update, and delete privileges across the application. They can manage user roles, delete records, and override the five-minute edit restriction whenever historical record updates are required.

Audit Integrity Assurance

Every modification to an incident is permanently recorded in the **History Timeline**. The audit trail captures the user, timestamp, status transition, assignment details, and change comments. This history cannot be modified or deleted. Automated ETL monitoring records also remain completely immutable to preserve audit integrity.

Operational Modules

Dashboard

Displays overall availability, unplanned/planned downtime, MTTR, replication health, and backup compliance across all platforms using standardised green/red traffic-light indicators.

Incident Register

Records unplanned outages. Automatically calculates ongoing downtime until marked as resolved. Resolution times are recorded as immutable database timestamps.

Backup & Recovery

Registers backup types, success outcomes, and recovery tests. Validates disaster recovery compliance and backup durability statistics.

Maintenance Register

Tracks OS patching, software upgrades, and planned database modifications separately to isolate operational incidents from planned downtime.

Capacity Tracking

Assists administrators by tracking storage trends, identifying the largest database tables, and projecting storage exhaustion dates for proactive planning.

Replication & Health

Monitors replica lag and core metrics (CPU, Memory, Disk, and connections) for Oracle, MySQL, PostgreSQL, and MS SQL Server environments.

Data Integration

Automated Data Collection (ETL)

Scheduled monitoring scripts run directly on targets to collect metrics like CPU usage, disk space, and replication lag. They transmit this data securely to the Hub API. Records created via scripts are labeled as created by System or Script users.

Excel Integration

Operational data stored within the MySQL backend is exposed through specific database views, allowing Microsoft Excel and Power BI to fetch records directly via an ODBC connection for advanced charting and external SLA reporting.

Best Practices

  • Record incident tickets immediately upon occurrence.
  • Document all planned maintenance outages in advance.
  • Perform and record disaster recovery testing regularly.
  • Monitor Dashboard traffic-light indicators daily.
  • Investigate SLA target breaches immediately.
  • Ensure automated server monitoring agents remain active.
  • Refresh ODBC-connected Excel reporting dashboards regularly.
  • Maintain clean, accurate records for all manual entries.
